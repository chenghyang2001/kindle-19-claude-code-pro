# 安全性審查（Security Review）

## 用途
處理使用者輸入、資料庫查詢、認證或 API key 的程式碼上線前，做一次聚焦在安全的審查。

## 變數
| 變數 | 說明 | 範例 |
| --- | --- | --- |
| `{{entry_points}}` | 外部輸入從哪裡進來 | HTTP query string、表單 |
| `{{threats}}` | 要特別檢查的威脅類別 | SQL 注入, XSS, 機密外洩 |
| `{{code}}` | 程式碼 | （貼上程式碼） |

## 模板
---
你是一位應用程式安全稽核員，假設攻擊者會嘗試所有輸入路徑。

外部輸入的進入點：{{entry_points}}
請檢查以下威脅：{{threats}}

對每個威脅：
1. 判定「有風險 / 無風險 / 無法判斷」。
2. 有風險時寫出一個具體的攻擊輸入範例，以及它會造成的後果。
3. 給出最小修正方式（參數化查詢、跳脫、改用環境變數等）。

不要提出與上述威脅無關的風格建議。

程式碼：
```
{{code}}
```

輸出格式：Markdown 表格（威脅 / 判定 / 攻擊範例 / 修正），表格後一段「最優先修的一項」。
---

## 範例填入
- entry_points = `Flask 路由的 request.args["id"]`
- threats = `SQL 注入, 錯誤訊息洩漏內部資訊`
- code = `cursor.execute(f"SELECT * FROM rooms WHERE id = {request.args['id']}")`

## 預期輸出格式
```
| 威脅 | 判定 | 攻擊範例 | 修正 |
| SQL 注入 | 有風險 | ?id=1 OR 1=1 | cursor.execute("... id = %s", (room_id,)) |
最優先修的一項：SQL 注入。
```

## 使用說明
`threats` 不要一次塞十幾項，3～5 項 Claude 會檢查得比較深。
