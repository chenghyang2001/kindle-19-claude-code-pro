# 程式碼審查（Code Review）

## 用途
PR 送出前、或接手別人的程式碼時，讓 Claude 依「指定標準」逐項審查，而不是泛泛地說「看起來不錯」。

## 變數
| 變數 | 說明 | 範例 |
| --- | --- | --- |
| `{{language}}` | 程式語言 | Python |
| `{{standards}}` | 要套用的審查標準（逗號分隔） | 正確性, 錯誤處理, 命名, 安全性 |
| `{{context}}` | 這段程式在系統中的角色 | 電商訂單金額計算 |
| `{{code}}` | 要審查的程式碼 | （貼上程式碼） |

## 模板
---
你是一位資深 {{language}} 工程師，負責審查團隊的程式碼。

背景：這段程式用於「{{context}}」。

請只依照以下標準審查：{{standards}}。
規則：
1. 每個問題都要指出行號或函式名稱，並說明「為什麼是問題」。
2. 依嚴重度分為 🔴 必改、🟡 建議、🟢 備註。
3. 每個 🔴 問題附上修正後的程式碼片段。
4. 不要評論標準以外的項目；沒有問題的標準直接寫「無問題」。

程式碼：
```
{{code}}
```

輸出格式：先一行總評，再用 Markdown 表格列出問題（欄位：嚴重度 / 位置 / 問題 / 建議），最後附 🔴 項目的修正碼。
---

## 範例填入
- language = `Python`
- standards = `正確性, 錯誤處理, 邊界值`
- context = `電商訂單金額計算`
- code = `samples/order_utils.py` 全文

## 預期輸出格式
```
總評：有 1 個必改問題（空清單除以零）。
| 嚴重度 | 位置 | 問題 | 建議 |
| 🔴 | average_price | 空清單 ZeroDivisionError | 先檢查 len(items) |
...
修正碼：...
```

## 使用說明
`standards` 越具體越好（例如「OWASP A03 注入」比「安全性」好）。審查大檔時分段貼上，每段重用同一個模板。
