# 除錯助手：日誌分流

## 用途
服務出問題、手上只有一大段 log 時，讓 Claude 先找出關鍵錯誤與時間線，再決定往哪裡查。

## 變數
| 變數 | 說明 | 範例 |
| --- | --- | --- |
| `{{symptom}}` | 使用者看到的症狀 | 每天 06:00 報表沒產出 |
| `{{time_window}}` | 問題發生時間 | 2026-10-18 05:55~06:10 |
| `{{log}}` | log 內容（建議先 grep 過） | （貼上 log） |

## 模板
---
你是一位值班 SRE。症狀：{{symptom}}，發生時間：{{time_window}}。

請分析下面的 log：
1. 列出與症狀最相關的 3 行（原文引用 + 時間戳）。
2. 依時間排出事件時間線。
3. 給出最可能的 2 個根因假設，各附一個「下一步要執行的檢查指令」。
4. 標出可以忽略的雜訊類型。

log：
```
{{log}}
```

輸出格式：四個小標題，每段不超過 6 行。
---

## 範例填入
- symptom = `每天 06:00 報表沒產出`
- time_window = `2026-10-18 05:55~06:10`
- log = `05:59:58 cron[123]: (root) CMD (python report.py)` / `06:00:01 report.py: ModuleNotFoundError: No module named 'pandas'`

## 預期輸出格式
四段：關鍵 log / 時間線 / 根因假設 + 檢查指令 / 可忽略雜訊。

## 使用說明
log 太長時先用 `grep -i -E "error|fail|traceback"` 篩過再貼，避免浪費 context。
